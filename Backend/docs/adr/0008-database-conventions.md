# 0008 — Database conventions (UTC-naive DATETIME2, naming, frozen migrations, where the access rule lives)

**Status:** accepted · **Date:** 2026-10-05

## Context
One `analyses` table (D-03) must run on SQL Server in production and SQLite in fast tests, with deterministic migrations.

## Decision
- Datetimes are **UTC-naive `DATETIME2(3)`**, converted to aware UTC (`…Z`) at the schema boundary. Python values are
  truncated to milliseconds.
- Portable SQLAlchemy types (`Uuid` → UNIQUEIDENTIFIER, `JSON` → NVARCHAR(MAX), `Boolean` → BIT) with an MSSQL
  `DATETIME2` variant.
- Latitude/longitude are `DECIMAL(9,6)` in SQL Server but plain floats in Python (`asdecimal=False`).
- Metadata naming convention (`pk_`/`ix_`/`ck_`/`fk_`/`uq_`). Migrations spell every constraint and index name literally
  and **never import app code** (a migration is a frozen snapshot). Autogenerated migrations are hand-reviewed and
  `downgrade()` must work.
- The repository does *query* logic (scope/client filtering, pagination). The **access rule** (visible iff sample or owner,
  else 404) lives in the service.
- Engine injection (`create_app(engine=...)`) keeps tests hermetic. The lifespan degrades (warning, `/health/ready` 503)
  instead of crashing when SQL Server is down.

## Consequences
+ Portable, reviewable, testable.
− Two descriptions of the schema (model + migration) — guarded by `alembic check` in the tests.
